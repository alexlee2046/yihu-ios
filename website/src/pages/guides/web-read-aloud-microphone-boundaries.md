<h2 id="first-answer">网页能播放，不代表一呼提供内置朗读或语音通话后端</h2>

一呼围绕WebKit访问自有Agent工作台，增加原生转写和草稿交付。网页若提供朗读，其文字、声音、生成服务与播放控制仍由实际网页决定。源码允许内联媒体播放，不等于所有站点的TTS、连续双向语音或锁屏播放已适配。本页专门核对“刚在听网页，现在要说一句话”的切换边界，而不是重复耳机配对排障或认证任意语音Agent。

## 把输出与输入分开定位

**输出链**：网页是否有已获准的朗读功能、是否真的产生了可播放内容、手机输出到了哪里，是不同问题。一呼不提供通用TTS服务，不应把空白播放或网络失败都归因于耳机。

**采集链**：系统麦克风权限、网页采集请求和原生录音入口分别受各自规则约束。允许网页播放不是允许网页录音；打开页面也不自动授予原生或服务端写权限。

**交接链**：原生转写的文字可以尝试受守卫填入兼容草稿，不代表会发送；网页自己的语音会话则有其服务规则。两条路径不能互相冒充回执或兼容证明。

## 安全的单路径切换走读

1. 只在安全静止环境使用获准的合成内容。不要朗读顾客资料、私有任务或真实会议录音来复现问题。
2. 先辨认自己是否正在使用网页的语音/播放控制；通过它已有的停止或暂停动作结束本次输出，核对状态。不要同时开启网页录音与原生录音来试探并发能力。
3. 再检查系统麦克风、实际音频路由、模型和目标草稿。不要重置别人的会话、权限或系统设置；发生冲突时停止受影响路径，而不是不断点击录音。
4. 用“整理示例清单，只留草稿，不发送”测试原生输入。短语音可能自动尝试安全填入，因此先选目标，再核对文字是否已经出现。
5. 结果不明就保留原文并检查目标已有内容；不通过换页面、换编辑器或清标记绕过拒绝。最后结束自己开启的播放/录音，保留对问题层级的描述。

这是检查顺序建议，不是本轮已完成的浏览器/真机测试；也不提供操作系统级麦克风占用探针、通用冲突检测面板或自动资源仲裁功能。

## 朗读内容和记录副本

网页TTS是否向服务发送文字、保存音频或同步历史，应看该服务规则，不由端侧ASR推断。原生转写在准备好的模型上本地处理，也不等于后续网页草稿永不离开手机。暂停播放、停止录音与删除服务副本分别是不同动作；不要据停止按钮承诺数据已撤回。

## FAQ

<h3 id="faq-native-tts">一呼是否给所有Agent网页增加统一朗读按钮？</h3>

本页不作这种承诺。当前范围是浏览器壳与原生语音草稿等增强，朗读若存在由实际网页/服务提供；内联媒体配置不是统一TTS功能。

<h3 id="faq-concurrent">网页和原生麦克风能一直同时使用吗？</h3>

没有本轮并发矩阵可支持这个保证。先按单一路径切换并观察权限、路由和中断；不以反复启动制造冲突或绕过系统提示。

<h3 id="faq-autoplay">允许内联播放是否等于自动播放和锁屏都必定可用？</h3>

不等于。页面实现、系统策略、音频会话和实际版本仍有影响；源码配置不证明所有站点或后台场景已经验证。

<h3 id="faq-permission">网页能朗读就已获准录音吗？</h3>

不能这样推断。媒体输出、麦克风权限、页面采集及服务端身份/写权限是不同层级，须按实际提示单独确认。

<h3 id="faq-loopback">如何确认朗读没有被当作自己的输入？</h3>

先停止本次播放，再用单一合成语句检查实际转写。是否存在回采或回声需要具体设备证据；voiceChat等配置不是零回声或声纹准确保证。

<h3 id="faq-stop">停止网页语音能撤回已经交给服务的数据吗？</h3>

不能据此承诺。停止与撤回、第三方存储和历史同步不同，需按实际服务规则核对；本页不提供统一远端删除功能。
