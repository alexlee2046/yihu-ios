<h2 id="first-answer">先核医院原预约，再核资料由谁带、谁接谁送；发出清单不等陪诊安排已确认</h2>

家人轮流陪老人复诊，容易漏掉的不是再写一份病情摘要，而是预约是否有变、到哪个院区、资料谁保管、去程返程谁负责。先经本人同意，在医院认可的原渠道核这些安排，再把非敏感的待确认事项交给实际负责的人。不要把群里“看到了”、工作台草稿或服务回执当作挂号成功、接送落实或本人授权。病情、检查结果、用药和临床交接留在医院规定的渠道；突发不适或紧急情况不等这份清单和消息回执。

## 适用范围：复诊陪同的行政分工，不是医疗交班

这份清单面向家庭成员轮流陪诊时的安排核对，不替代医院就诊须知。陪同不自动授予查看记录、代签、代领资料或替本人决定的权利；需要代理时，向医院确认实际手续与授权。不要在这张表、未经批准的设备或工作台中填写姓名、证件号、预约码、联系方式、病史、检验结果或用药内容。实际证件与医疗资料仅在本人同意且医院认可的原渠道流转。

一呼可在模型、权限和兼容工作台满足条件时整理语音文字和录音笔记、准备草稿；它不是挂号、医疗记录、家庭成员授权或接送调度系统，不会联系医院、预约车辆、评估老人是否适合某种交通方式。录音另核本人许可与医院规则；不能获准时不用录音。本机识别不等于目标不保存或不同步，另存前核设备、位置、账号及访问范围。

| 返程接送 | 实际负责人与原安排 | 谁核返程、是否仍待确认 | 不根据预计就诊结束时间保证接回时间 |

| 待问事项 | 本人同意的原问题列表 | 行政疑问类别及由谁向医院问 | 诊疗问题直接找专业人员，不让转写补答案 |

## 用一呼整理时按这个顺序做

1. **先征得同意并核原安排。** 没有读取权限就由本人或获授权人员在原渠道核，不借账号、不导出完整预约或医疗档案。
2. **只留行政范围。** 草稿分“已核安排、待确认项、下一步由谁核”。未确认的分工明确保留，不把意向写成承诺。
3. **逐字核关键项。** 比对日期、院区、到达要求、去返程分工与否定词。“尚未确认接送”不能被转写或整理成“已确认”。录音顺序不是事件顺序。
4. **核目标和原尝试。** 显式填入绑定打开笔记时的工作台与页面，目标变了先停；不是所有网页都支持填入。草稿出现不代表已发送，更不代表医院已登记。
5. **分别取得对应反馈。** 由实际负责的人在原获准渠道确认其范围；发送回执不等接送人接受，资料类别已核不等资料真实齐全。没有反馈就保留待确认。
6. **不确定就停并查原记录。** 笔记一次交接标记涵盖直接填入与暂存，失败或未知不能清标记、改名或换目标盲重发。新操作不能证明旧操作，复制也可能留下重复副本。

直接填入有 3,000 个 Swift Character 长度门槛，长笔记沿用 Markdown 附件暂存路径；暂存、上传、发送与人员接受是不同阶段。不能把附件路径当绕过拒绝的方法。本页没有新增离线待发箱、自动通知、自动重试、跨目标去重或撤回所有副本的能力。网络恢复不等于预约与接送安排仍适用。

## 常见问题

<h3 id="faq-booking">把清单发给家人就算预约确认了吗？</h3>

不算。预约以医院原渠道为准，家庭分工以对应人员的明确反馈为准；发送成功不能替代这两项。

<h3 id="faq-documents">可以把病历、证件和预约码都放进下载表吗？</h3>

不要。此表只核资料类别和行政交接范围；原件与医疗内容留在本人同意且医院认可的渠道，不通过本页或未经批准的工作台处理。

<h3 id="faq-clinical">复诊前要停药或禁食吗？</h3>

本页不提供此类建议。按医院和专业人员针对本人的要求核实，不能从别人的经历或语音草稿推断。

<h3 id="faq-consent">陪诊人能代签或自动获得看病历权限吗？</h3>

不能由陪同关系推断。按本人意愿、医院实际规则和相应授权手续处理，本表不是授权或身份核验凭据。

<h3 id="faq-transport">接送人没回消息，一呼会自动催促或安排车辆吗？</h3>

不会由本页作此承诺。未回仍是待确认，沿原联络方式核实；需要专业协助或安全判断时找相关服务人员，不由清单评估。

<h3 id="faq-retry">填入后网页重载，可以再交接一次吗？</h3>

先查原目标。重载、无回执或网络恢复都不能证明原操作没发生。不绕过一次交接标记，不用新操作替旧操作补证；急事按已有可靠渠道处理。
