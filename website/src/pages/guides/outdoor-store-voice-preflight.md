<h2 id="first-answer">这是一份安全静止时的文字工作流，不是对讲部署教程</h2>

一呼可围绕自有 Agent 网页工作台，把手机转写、录音笔记和已有 JSON 台账串成可核对的文字流程。户外骑行应停车并到安全位置再操作；门店应避开热源、车辆和正在服务的区域。蓝牙耳机配对不等于当前录音输入正确，也不等于多人免提对讲可用。即时联络、紧急通知和现场安全调度需要另有经验证的通信方式，不能依赖本指南。

## 先准备一个不会执行真实任务的样例

自行构建并签名一呼，准备可用的兼容模型、麦克风权限和你有权访问的可信 HTTPS 工作台。选一个空白草稿框，确认输入不会自动提交；不要测试到已有订单、客户沟通、付款或生产指令里。本页和官网演示不会接入麦克风、真实工作台或客户数据。

**合成语句**：“整理一份示例物品检查清单，只留草稿，不发送、不下单、不执行。”这条语句是流程示意，不是已经跑过的真机用例。先明确目标，再选择短语音草稿或录音笔记一条路径；不要把同一段内容同时交接两次。

## 户外骑行：停车后的记录路径

1. **先停稳并选择安全位置**，不要在行驶、过路口、下坡或需要注意环境时操作手机或隔绝环境声。头盔耳机和 AirPods 没有由本轮验证为一呼兼容设备。
2. **核对音频与模型**。风、头盔遮挡和输入切换都可能影响实际录音；源码设置音频处理不等于实测风噪指标。若环境不适合，改用安全的手动记录或推迟。
3. **区分本地与远端**。模型已就绪时的手机处理、保存音频以及网页可达是三件事。没有网络时不要承诺上传、回复或网页草稿同步；缓存卡片也不是本次成功刷新。
4. **只走合成草稿**。转写完成后核对文字和目标。已有填入只检查不重复；未知编辑器或宿主拒绝不绕过。结果不明先留原文，使用既有通信方式处理真正紧急事项。

## 餐饮/酒店/零售门店：非紧急记录的交接路径

把演练限定为不含订单和个人信息的内部样例，例如整理下次例会要核对的三个设备问题。录音前确认现场参与者知情、权限和服务规则；不要把顾客对话、餐桌信息或员工私密内容当演示材料。

在静止安全处打开正确工作台，选短转写草稿或录音笔记。短语音可能自动尝试受守卫填入，因此先核对目的地；结束录音笔记则不等于已经交给 Agent。笔记的显式填入/分享暂存先保留一次交接标记，结果不确定也不自动重试或换另一条交接路径。核对目的地已有内容后再决定是否手动复制。

若团队自行把设备检查或询盘跟进事项导出成 Radar JSON，只读筛选不会修改台账。所谓“外贸雷达”在这里仅指自有任务数据的解释与阅读，不是外贸商机抓取、自动采购、自动发信或实时门店调度系统。任何真实回复仍需独立写权限、手机确认与回执，不能由本页走读代替服务验收。

## FAQ

<h3 id="faq-hands-free">能用耳机按键或语音一直免按键调度吗？</h3>

本指南不提供这种承诺。蓝牙会话配置不是耳机按键触发、锁屏唤醒或持续群组对讲的证据。当前候选只是安全静止时的音频预检和文字交接。

<h3 id="faq-wind">voiceChat 模式是否保证骑行风噪被消除？</h3>

不保证。它是源码中的系统音频模式请求，不是特定耳机、风速、头盔或骑行条件下的测试成绩。环境影响识别时应停止并改用适当方法。

<h3 id="faq-offline">弱网下是否可以完全离线完成工作流？</h3>

不能这样概括。已就绪模型、本地笔记和既有快照有本地处理路径，模型下载、网页、附件交接和服务回复分别有网络与权限前提。应明确停在哪一步而不是统称“全部离线”。

<h3 id="faq-minutes">录音结束后就生成可信的 AI 会议纪要了吗？</h3>

没有。一呼源码提供分段转写和原文保存；核对、摘要和行动项整理需要另走获准流程。识别文本可能错误，保存本地也不代表备份与后续交接副本都不存在。

<h3 id="faq-interruption">换耳机或来电后是否能保证录音无损继续？</h3>

不能。源码包含输入变化处理以及中断/失败提示，但不是所有设备与干扰组合的验收。检查保存状态、音频和转写接缝；不要用恢复路径的存在宣称绝不丢字。

<h3 id="faq-urgent">门店紧急调度能把草稿填入当作送达吗？</h3>

不能。草稿、上传、发送、回执和对方处理分别是不同状态。本页不做时延、覆盖距离或生产送达承诺；紧急事项应使用已有经验证的联络与安全流程。
