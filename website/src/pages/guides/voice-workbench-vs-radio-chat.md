<h2 id="first-answer">先看接收方：Agent 草稿不等于人与人对讲</h2>

一呼是访问自有 HTTPS Agent 工作台的 iOS 浏览器壳，增加手机端语音转写、录音笔记与 PM Radar JSON 读取。传统对讲机用于符合设备制式与当地规则的无线通话；普通语音群聊用于相应服务里的联系人或群组。若需求是持续的人与人现场调度，不应把一呼当作已经验证的对讲机或语音群聊替代品。下表比较使用边界，不是三种方案的实测排名。

## 先分清三种交接

- **对人说话**：先确认收听人、通信制式或服务、现场权限和备用联络方式。不同对讲机与聊天软件的能力不能一概而论。
- **把想法交给 Agent**：先选工作台与页面草稿框，再使用已配置模型的手机转写；草稿填入不是消息发送，更不是任务执行。
- **先保留记录**：录音笔记保留本地音频和文字，核对后再显式交接。会议记录不自动变成确认无误的纪要或分配给团队的任务。

## 蓝牙音频预检不是免提通话认证

`CollieAudioCapturePreferences` 的近场模式配置了 `playAndRecord`、`voiceChat` 和 `allowBluetoothHFP`；关闭近场时配置不同。这说明源码会请求相应音频会话，不证明某一款 AirPods、头盔耳机或蓝牙适配器已通过真机验证，也不证明风噪抑制、回声控制或长时续航达标。

在安全静止环境先确认系统输入、输出及录音权限，用一条无真实任务的合成语句检查转写和草稿目标。更换耳机、来电或音频服务重置后重新检查。录音笔记源码有输入设备变化后的重定向和失败提示路径；不能由此保证中断无损恢复。不得在行驶中操作手机或为了测试绕过宿主拒绝。

## 离线、会议与外贸需求怎样分流

**弱网或离线**：已下载且可用的模型与本地音频不等于网页可访问。缓存卡片只是既有快照，失败或旧来源须显示；不要把点刷新、蓝牙已连接或本地识别完成当作远端已收到。

**AI 会议录音纪要**：一呼提供的是录音、分段转写和保留原文，会议纪要需要另外核对并在获准的目标流程里整理。本页不承诺说话人分离、自动提炼行动项或识别准确率；录音前确认参与者知情和适用规则。

**外贸雷达**：若你的自有台账把询盘或跟进任务导出为符合 PM Radar 契约的 JSON，可按项目与状态阅读；这不是内置海关数据库、市场情报订阅、客户资料搜集或自动发信服务。`tasks` 与 `decisions`、来源时间、缓存状态以及写授权仍须分别核对。

## FAQ

<h3 id="faq-radio-replacement">一呼能直接替换门店或车队对讲机吗？</h3>

不能据当前源码这样承诺。它的交接对象是自己的工作台草稿，不是已验收的多人语音频道。现场实时联络应另选符合条件的设备/服务并做当地环境验证；一呼可在安全静止时辅助整理文字记录。

<h3 id="faq-airpods">蓝牙耳机已连接，是否代表一呼正在使用耳机麦克风？</h3>

不代表。配对状态、实际输入路由和当前音频会话是不同事实。需要在实际设备上核对输入、输出和合成录音结果；源码选项不替代耳机型号兼容证明。

<h3 id="faq-watch">Apple Watch 能作为独立对讲或审批终端吗？</h3>

当前 Watch 伴侣接收配对手机的既有摘要并接续到手机，需配对及系统条件。它不提供本页承诺的独立对讲、台账刷新或独立审批；手机确认与服务端授权仍独立存在。

<h3 id="faq-weak-network">没有网络时转写完成，能算已经交付吗？</h3>

不能。识别文字只说明该处理步骤有结果。网页、附件上传或真实回复仍依赖目标服务与权限。结果不确定先保留原文并核对目的地，不自动重试。

<h3 id="faq-trade-radar">外贸团队可以导入询盘任务吗？</h3>

只有在团队有权使用并自行导出符合模型契约的 JSON 时才可按现有 Radar 规则阅读。来源身份、字段、日期与缓存必须明确；本页不新增外贸数据源、客户名单、通知后台或自动跟进。

<h3 id="faq-install">在哪里下载 App Store 成品？</h3>

当前是源码发行，没有已发布成品链接。请按构建指南使用自己的签名、模型和工作台。本页不会用虚构商店链接或“已上线源码”替代安装与设备验收。
